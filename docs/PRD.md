## 1. 产品概述

### 1.1 一句话定义

DayCell 是一个**以「一天」为容器**的记录本：把当天的待办、碎片想法、花费沉在同一个格子里。**打开即落在今天**——日视图写当天，周视图看内容，月视图看密度。

### 1.2 它刻意不是什么

- **不是日历**：不碰时间点。"下午三点开会"不归它管，交给系统日历。
- **不是 todo 软件**：没有优先级、标签、项目、子任务、拖拽排序。待办只是"一天"的一个切面。
- **不是记账软件**：不记收入、不做预算、不做报表。花费只是"一天"的一个切面。
- **不是社交平台**：无账号、无关注、无分享流。

### 1.3 目标用户

主用户是产品负责人本人，**主要在手机上使用**，电脑偶尔。次要用户是少量亲友（拿到链接即用，各自数据独立、互不同步）。

### 1.4 两条产品红线

任何需求都要先过这两条：

1. **写入必须极快**：从"想记"到"记下" ≤ 5 秒。做不到，"当日想法"就不会有内容，产品退化成空壳。
2. **回看必须有价值**：打开上个月能看出"哪几天认真活过"。做不到，产品退化成又一个 todo 软件。

> ⚠️ **已知风险**：v0 移除了「当日总结」和「心情评分」后，红线 2 目前只由"周视图正文 + 花费三级汇总"承担。花费能回答"钱去哪了"，回答不了"那天过得怎么样"。见 §11 未决问题。

> ⚠️ **红线 1 与红线 2 的取舍（v6 决定）**：默认视图从周视图改为**日视图（今天）**，红线 1 的写入路径压到 **0 次切换**；代价是红线 2 的回看从"开屏即见本月密度"变成**多一次视图切换**。
> 理由：每天打开 App 的高频动作是"记今天"，不是"看这个月"；回看是低频行为（§1.5 目标是每周 ≥1 次），多一次点击可接受。
> **缓解措施**：周/月视图必须一次切换可达（切换器常驻，不藏进菜单）；日视图顶部保留"回到本周/本月"的入口。

> ⚠️ **红线 1 的第二次收敛（v6.1 决定）**：顶部常驻的快捷录入行（待办/想法/花费 三标签 + 输入框 + 「→ 今天」徽标）被**整行移除**，录入入口收敛为**日详情各区块的内联表单**一个（原 M7 废除，M8 成为唯一入口）。
> 补速手段：**完全空白的一天自动展开待办表单并聚焦**——"落地即写"仍是 0 次多余点击。
> **代价**：今天已经有内容时表单不自动展开（不能挡内容），要先点一次「+ 添加」，**比 v6 多一次点击**。完整理由见 D18。

### 1.5 成功的样子

上线 4 周后，主用户：
- 每周至少 5 天有记录（待办/想法/花费任一）
- 每周至少打开 1 次周视图回看
- 从未因"太麻烦"而放弃记录

## 2. 用户场景

### 场景 A：早上列今天要做的事（手机，站立，30 秒）
> 通勤路上想起三件事。打开 DayCell（已加到主屏，秒开），**落地就是今天的日视图**。今天还空着，待办输入框**已经自动展开并聚焦**——直接敲"回客户邮件"、回车，再敲两条。**全程没有离开首屏，没有切视图，没有点选日期，一次多余的按钮都没点。**

> 如果今天已经有内容（第二天以后的常态），表单不会自动展开——它不能挡住已有内容。此时先点一下待办区的「+ 添加」，再敲字回车。**这比 v6 多一次点击**，是移除顶部框的代价（D18 已明确接受）。

**这个场景对应红线 1**。它是产品成败的关键路径。

### 场景 B：随手记一个念头（手机，3 秒）
> 开会时冒出一个想法。打开应用（今天的日视图），点想法区的「+ 添加」——textarea 已聚焦，说一句话（用输入法自带的语音键），按「保存」。
>
> 手机没有 ⌘/Ctrl 键，所以多行想法的提交**必须有可点的「保存」按钮**，不能只靠快捷键（桌面才是 ⌘/Ctrl+回车）。

### 场景 C：补记前天的账（手机，精确路径）
> 想起来前天打车花了 45。**在日视图往前滑两天**（或直接按两次「前一天」）→ 花费区「+ 记一笔」→ 选分类、填金额、写备注 → 保存。**表单不关闭**，接着把当天另一笔也记了。记完滑回今天。

**v6.1 之后这个场景不再需要"两条路径"来解释**：录入入口只剩分区内联表单一个，它的写入目标**恒为你正在看的那一天**。以前顶部框快但写死今天、分区表单能写任意一天，两者并存既制造了 Q2 记的别扭点，也埋着"看着 9/25 却存进 9/29"的错记风险（当时只能靠一个 warn 徽标 + toast 打补丁）。现在这一整类错误**在结构上不可能发生**。

### 场景 D：周日晚上回看这一周（电脑，5 分钟）
> 打开桌面版（落地仍是今天的日详情），点一下切到**周视图**。7 行铺开，每行能看到当天做了什么、想了什么、花了多少。顶部汇总条显示"待办 12/18 · 4 天有想法 · 本周支出 ¥842.30"。

**这个场景对应红线 2**。

### 场景 E：月底扫一眼这个月（手机或电脑）
> 切到月视图。不看内容，只看**密度**：哪些格子有 `3/5` 的待办进度、`●2` 的想法标记、`¥129` 的花费。一眼看出这个月哪几天是实的、哪几天是空的。

## 4. 用户故事与验收标准

> 格式：Given（前提）/ When（动作）/ Then（可观察结果）。**每条 Then 都必须能被自动化测试断言。**

### US-01 快速记一条今天的待办（红线 1，v6.1 重写）
- **Given** 应用刚打开，落地在今天的日视图，且今天三类内容**皆空**
- **When** 不做任何点击，直接输入"回客户邮件"并按回车
- **Then**
  - 待办输入框**已自动展开且已聚焦**（`document.activeElement` 即该输入框）
  - 该待办出现在**今天**（= 当前选中日）的待办区块
  - 输入框清空、焦点保留、可立即输入下一条
  - 从聚焦到落库 **≤ 100 ms**；从打开应用到完成记录 **≤ 5 s**

- **Given** 今天已有内容（表单不自动展开）
- **When** 点待办区「+ 添加」，输入并回车
- **Then** 结果同上；**从打开应用到落库比 v6 多一次点击**（D18 已接受的代价）

- **And**（结构性保证，取代原"徽标高亮 + toast 提示今天"那两条）
  - 录入入口只有分区内联表单一个，写入目标**恒等于当前正在看的那一天**
  - 因此**不存在**"看着 A 天却写进今天"的代码路径，也**不需要**「→ 今天」徽标与相关 toast
  - 用户主动收起过某一天的自动表单后，**再次进入该日不再自动展开**（按日期记 `formDismissed`，不传染到别的日子）

### US-02 补记某一天的花费（精确路径）
- **Given** 月视图中选中 2026-09-27，日详情已展开
- **When** 点花费区「+ 记一笔」，选分类「餐饮」、金额填 `268`、备注填"中秋家宴"，按回车
- **Then**
  - 这笔支出归属 **2026-09-27**，不是今天
  - 日详情合计更新为 `¥500.00`（含原有两笔）
  - 分类汇总按金额降序更新
  - 月格 09-27 的金额更新为 `¥500`
  - 周视图（若该日在本周）行内金额与分类明细同步更新
  - **表单保持展开并清空**，可连续录入
  - 分类选择器记住"餐饮"，下次展开默认选中

### US-03 金额校验
- **Given** 花费表单已展开
- **When** 分别提交：空、`0`、`-5`、`abc`、`1e3`、`28.555`
- **Then**
  - 空 / `0` / 负数 / 非数字 → **拒绝**，toast 提示"请填写正确的金额"，焦点回到金额框，不落库
  - `1e3` → 按 `parseFloat` 解析为 1000（可接受）
  - `28.555` → 四舍五入到分，存 `2856` 分，显示 `¥28.56`
  - 金额内部一律以**整数「分」**存储与运算，任何汇总不得出现 `0.30000000000000004`
  - **不得用 `Math.round(parseFloat(x) * 100)`**：`1.005 * 100 === 100.49999999999999`，会少记一分。标准十进制必须走字符串逐位运算，第三位小数 round half up
  - 归一化规则见 `core/validate.ts normalizeNumericInput`：全角数字 `０-９`、全角句点 `．`、句号 `。` → 半角；千分位 `,` / `，` 去掉；**只 trim 首尾空白**（`'1 200'` 应拒绝）；**不接受 `¥` / `￥` 前缀**（是否放宽见 §11 Q6）
  - `parseAmount` 是 `ParseResult<number>` 纯函数；任何 UI 侧的同名逻辑必须与它**逐位一致**（当前由 `src/prototype-parity.test.ts` 强制）

### US-04 待办跨天顺延
- **Given** 2026-09-28 有 2 条未完成待办，且它们都未标记 `rolledTo`
- **When** 选中 2026-09-29，点顺延横幅的「顺延」
- **Then**
  - 09-29 新增 2 条待办，各带 `rolledFrom='2026-09-28'`，界面显示"顺延自 9/28"
  - 09-28 原两条标记 `rolledTo='2026-09-29'`，**视觉淡化**（opacity ≈ 0.42）并显示"已顺延 →"
  - 09-28 的待办进度**排除已顺延项**（原 `1/3` 变为 `1/1`）
  - 横幅消失，且刷新后不再出现（记录 `rollDismissed`）
  - **同一条待办不能被顺延两次**（`rolledTo` 已存在则跳过）

### US-05 顺延横幅的忽略
- **Given** 顺延横幅可见
- **When** 点「忽略」
- **Then** 横幅消失，源数据不变；再次进入该日不再显示

### US-06 月视图密度一览
- **Given** 2026 年 9 月有 16 天存在记录
- **When** 切到月视图
- **Then**
  - 渲染 42 个格子（6 行 × 7 列），**非本月日期灰显但可点击**
  - 每格最多显示：日期数字、单行标签、待办进度、想法条数、当日花费
  - 标题栏显示 `2026 年 9 月` + `16 天有记录 · ¥4609.80`
  - 今天是当前日期时，日期数字用强调色圆形底

### US-07 格子单行标签优先级
- **Given** 任意日期
- **When** 渲染月格或周行的标签位
- **Then** 按以下优先级**只显示一个**：
  ```
  当天纪念日  >  节日/农历初一  >  节气  >  农历日
  ```
  - 2026-09-25 → `中秋节`（不显示"十五"）
  - 2026-09-30 → `体检`（当天纪念日，压过农历"二十"）
  - 2026-09-07 → `白露`（节气）
  - 2026-09-19 → `初九`（被过滤的"全民国防教育日"不得出现）
  - **日详情不受此限制**：节日当天同时显示两者，如「中秋节 · 十五」
  - **任何日期都不得出现倒数**（"X 天后"）

### US-08 周视图回顾
- **Given** 当前周为 2026-09-28 ~ 2026-10-04
- **When** 切到周视图（**v6 起不再是默认视图**，默认为日视图）
- **Then**
  - **7 行竖排**，每行左侧日期+周几，右侧内容
  - 每行最多显示：待办前 3 条（含勾选态，多余显示 `+N 项待办`）、想法前 2 条（每条最多 2 行截断）、当日花费金额、分类明细
  - 顶部汇总条显示 `待办 n/m · k 天有想法` 与右对齐的 `本周支出 ¥xxx.xx`
  - 全空的一天显示"空白的一天"
  - 周起始为**周一**

### US-09 视图切换与日视图的进出（v6 重写，原为"手机 sheet"）
- **Given** 应用刚打开
- **Then** 落地在**日视图**，显示**今天**；切换器常驻且顺序为 **日 → 周 → 月**

- **When** 在日视图左右滑动（或点「前一天 / 后一天」）
- **Then**
  - 切到相邻日期，**保留当前视图**（不会跳回周/月）
  - 日期标题同步更新，含星期与农历标签（优先级见 US-07）
  - 切到非今天时，出现「回到今天」入口；切到今天时该入口消失
  - 单日渲染 ≤ 30 ms（§5.1），滑动过程不得出现白屏闪烁

- **When** 在周视图或月视图点击某一天的格子
- **Then**
  - **手机**：跳转到该日的日视图（全屏，非弹层）
  - **桌面**：右侧日详情面板切换到该日，左侧日历保持不动
  - 日视图存在**返回路径**：手机左上「← 返回」回到来源视图（周/月）与来源位置；桌面 `Esc` 收起

- **When** 在日视图内展开分区表单
- **Then** 表单**自动滚入视野**；键盘弹起时输入框不被遮挡

- **When** 切换设备模式（桌面 ↔ 手机，跨 900 px 断点）
- **Then** 当前选中日期与当前视图**保留**，但布局状态（桌面分栏宽度等）重置

### US-10 导出与导入
- **Given** 库中有数据
- **When** 依次点三种导出
- **Then**
  - **Markdown**：按月一个文件，含待办（勾选态）、想法（含时间）、花费明细与当日合计、分类汇总
  - **CSV**：`date,category,note,amount` 四列，UTF-8 **带 BOM**（否则 Excel 打开中文乱码），金额以元为单位保留两位
  - **JSON**：整库快照，含 `schemaVersion`、`exportedAt`、全部记录（**含墓碑**）
- **When** 从一个 JSON 备份导入
- **Then**
  - 先**完整校验**再写入；校验失败 → 一条不写，现有数据不变，提示具体原因
  - `schemaVersion` 高于当前应用 → 拒绝，提示"请升级应用"
  - 低于当前 → 走迁移后导入
  - 导入采用**按 id 合并 + `updatedAt` 较新者胜**，不做整库覆盖
  - 导入前自动做一次当前库的 JSON 快照（防止误操作）

### US-11 离线与安装
- **Given** 首次通过 HTTPS 访问并已"添加到主屏幕"
- **When** 断网后从主屏打开
- **Then**
  - 应用正常启动，全部功能可用（读写本地库）
  - 农历/节气正常计算（离线库，无网络请求）
  - 除首屏静态资源外，**运行时零网络请求**

### US-12 农历与纪念日
- **Given** 用户创建了一个农历纪念日"妈妈生日 · 八月十五 · 每年重复"
- **When** 渲染任意年份的日历
- **Then**
  - 该纪念日落在**当年的农历八月十五对应的公历日**上（每年公历日期不同）
  - 当天月格标签显示"妈妈生日"（最高优先级）
  - 日详情显示纪念日徽章
  - **前后任何一天都不显示任何提示**
  - 遇到农历闰月：见 §7-E13

## 5. 非功能需求

### 5.1 性能预算

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 首屏 JS（gzip） | **≤ 80 KB** | 构建产物统计；农历库必须异步分包，不计入首屏 |
| 首次可交互（国内 4G） | ≤ 3 s | Lighthouse TTI |
| 二次打开 | ≤ 500 ms | SW 全缓存命中 |
| 单次写入落库 | ≤ 100 ms | `performance.now()` 包裹 |
| **日视图渲染（首屏关键路径）** | **≤ 30 ms** | 单日 3 次点查（todos/notes/expenses）；v6 起这是落地页，比周/月更敏感 |
| 日视图翻日 | ≤ 30 ms / 次 | 同上；**不得重新初始化 store** |
| 月视图渲染（10 年数据量） | ≤ 100 ms | 索引范围查询，**禁止全库载入内存** |
| 周视图渲染 | ≤ 50 ms | 7 天范围查询 |

### 5.2 容量目标

重度使用按 5 KB/天估算：10 年 ≈ 18 MB、≈ 4 万条记录。在此规模下所有性能指标不得降级。

### 5.3 兼容性

| 平台 | 最低版本 |
|---|---|
| iOS Safari（含 PWA） | **16.4+** |
| Chrome / Edge 桌面与安卓 | 最近两个大版本 |
| Firefox 桌面 | 最新版 |
| 屏幕宽度 | 320 px ~ 2560 px |

不支持 IE、不支持安卓 WebView 内的旧内核。检测到 IndexedDB 不可用时走 §7-E1 降级。

### 5.4 隐私

- v0 **无账号、无埋点、无统计、无 Cookie**
- 运行时不发起任何跨域请求
- 所有数据只存在本机浏览器
- 备份弹窗必须明示这一点

### 5.5 可访问性

- **全部操作可仅用键盘完成**（含展开表单、保存、取消、切日期、切视图）
- 正文对比度 ≥ 4.5:1，非文本元素 ≥ 3:1
- 所有可点元素有可访问名称（`aria-label` 或文本）
- 焦点顺序符合视觉顺序；**从周/月进入日视图时焦点移入日视图，返回时归还触发的格子**；视图切换器始终在 Tab 序内且可达
- 触摸目标 ≥ 40 × 40 px（月格除外，月格是密集网格，需保证 ≥ 44 px 高）

### 5.6 可移植性（架构约束）

`src/core/` **禁止 import React、禁止访问 DOM/`window`/`document`**。
理由：将来出微信小程序（Taro）时只重写 UI（约 30% 工作量）。此约束需用 ESLint 规则强制，不能靠自觉。

## 6. 数据模型

> ⚠️ **本节取代 `SPEC.md` §5 的旧模型。** 旧模型是"一天一个 DayEntry blob"，已废弃。

### 6.1 三条不可违背的存储规则

这三条是为将来加云同步预留的，**现在不遵守，将来就要重写存储层**：

1. **记录级存储**：每条待办 / 想法 / 花费都是**独立记录**，各自带 `date` 字段。**不得**把一天的内容打包成一个对象存储——否则两端同一天各改一处就会整天互相覆盖。
2. **软删除（墓碑）**：删除只置 `deleted: true` 并更新 `updatedAt`，**永不物理删除**。物理删除的记录在同步时会被对端"复活"。
3. **每条记录必有 `updatedAt`**：冲突策略 = 记录级 last-write-wins（不引入 CRDT）。

### 6.2 类型定义

```ts
/** 所有内容记录的公共字段 */
interface BaseRecord {
  id: string;          // crypto.randomUUID()，全局唯一、无需服务端
  date: string;        // 'YYYY-MM-DD'，归属日（浏览器本地时区）
  createdAt: number;   // epoch ms
  updatedAt: number;   // epoch ms，任何修改都必须刷新
  deleted: boolean;    // 墓碑标记
}

interface TodoRecord extends BaseRecord {
  type: 'todo';
  text: string;              // ≤ 500 字
  done: boolean;
  doneAt?: number;
  rolledFrom?: string;       // 顺延来源日期
  rolledTo?: string;         // 被顺延到的日期；存在即表示"已顺延出去"
}

interface NoteRecord extends BaseRecord {
  type: 'note';
  text: string;              // ≤ 5000 字，纯文本，保留换行，**不解析 Markdown**
  pinned?: boolean;          // v1 预留
}

interface ExpenseRecord extends BaseRecord {
  type: 'expense';
  amountCents: number;       // **整数「分」**，> 0
  catId: string;             // 指向 CategoryRecord.id
  note: string;              // ≤ 200 字，可为空串
}

interface AnniversaryRecord extends BaseRecord {
  type: 'anniversary';
  title: string;
  isLunar: boolean;          // true = 按农历重复
  repeat: 'none' | 'yearly';
  // date 字段：isLunar=false 时为公历日期；isLunar=true 时为农历日期（含闰月标记）
}

interface CategoryRecord {
  id: string;
  type: 'category';
  name: string;
  order: number;
  createdAt: number;
  updatedAt: number;
  deleted: boolean;          // 删除分类不影响历史支出，见 §7-E21
}

/** 键值单例设置 */
interface SettingRecord {
  key: string;               // 'accentColor' | 'lastBackupAt' | 'backupReminderOff' | 'onboarded' ...
  value: unknown;
  updatedAt: number;
}
```

### 6.3 IndexedDB 布局

数据库名 `daycell`，初始 `version = 1`。

| Store | 主键 | 索引 | 说明 |
|---|---|---|---|
| `todos` | `id` | `byDate(date)`、`byUpdated(updatedAt)` | |
| `notes` | `id` | `byDate(date)`、`byUpdated(updatedAt)` | |
| `expenses` | `id` | `byDate(date)`、`byUpdated(updatedAt)`、`byCat(catId)` | |
| `anniversaries` | `id` | `byDate(date)` | |
| `categories` | `id` | `byOrder(order)` | |
| `settings` | `key` | — | |

**为什么分 6 个 store 而不是一个大 store**：三类内容的访问模式不同（花费要按分类聚合、待办要过滤 `rolledTo`），分开后类型安全、查询无需复合索引。月视图需要 3 次并行范围查询，在 IndexedDB 里是毫秒级，可接受。

**`byUpdated` 索引是为同步预留的**：将来增量推送只需游标扫这个索引。

### 6.4 版本迁移

- 用 `onupgradeneeded` 里的 `oldVersion → newVersion` 分支写**显式**迁移步骤，禁止"删库重建"
- 每次迁移必须能被 §US-10 的导入流程复用（迁移函数是纯函数：`(records, fromVersion) => records`）
- 迁移失败 → 事务回滚，保留旧版本数据，提示用户导出备份

## 7. 边界与异常清单

> 这一节是验收的一部分。**每一条都要有对应的处理，且在测试里可断言。**

| # | 情况 | 处理 |
|---|---|---|
| E1 | **IndexedDB 不可用**（Safari 隐私模式、被策略禁用） | 降级到内存存储；顶部常驻**红色横幅**"当前数据不会保存"；导出按钮高亮；不阻塞使用 |
| E2 | **存储配额耗尽**（`QuotaExceededError`） | 写入失败时保留用户输入不清空，提示"存储空间不足，请导出备份后清理"，给出导出入口 |
| E3 | **iOS 7 天数据清除** | 首次启动引导"添加到主屏幕"（装成 PWA 后豁免 ITP 7 天清除）；配合 S2 的备份提醒 |
| E4 | **农历库异步 chunk 加载失败**（刚发版导致旧 hash 404） | 自动重试 1 次；仍失败则**只显示公历**，标签位留空，不报错、不白屏；下次启动重新加载 |
| E5 | 金额非法（空 / 0 / 负 / 非数字） | 拒绝 + 提示 + 焦点回金额框，见 US-03 |
| E6 | 金额精度溢出（`28.555`） | 四舍五入到分 |
| E7 | 金额过大（> 99,999,999 元） | 拒绝并提示，防止 `amountCents` 超出安全整数 |
| E8 | 文本超长（待办 > 500 字、想法 > 5000 字、备注 > 200 字） | 输入时计数并阻止超出，不允许静默截断 |
| E9 | 空文本 / 纯空白提交 | 拒绝，不落库 |
| E10 | 顺延源日无数据或全部已完成 | 不显示横幅（不是显示一个空的横幅） |
| E11 | **顺延循环**（A→B 后又想把 B→A） | `rolledTo` 已存在的记录不再参与顺延；顺延只发生一次 |
| E12 | 跨年/跨月翻页（12 月 → 次年 1 月） | 正常，标题栏年份随之更新；6 行月份完整显示 42 格，不裁成 5 行 |
| E13 | **农历闰月纪念日**（如"闰六月初一"生日，某年无闰六月） | 落在**该年的六月**同一天；界面标注"（今年无闰月，按六月计）"。三十日叠加时见 E25 |
| E14 | 农历表覆盖范围之外（`lunar-typescript` 支持 1900–2100） | 超出范围时标签位留空，不抛错。**注意：库对 1899/2101 并不抛错，会照常返回不可信结果**，范围判断必须由我们自己实现（`core/lunar.ts` 的 `inLunarRange`） |
| E15 | **设备时区变化 / 跨国际日期变更线** | `date` 一律用浏览器本地时区计算；时区变化后历史记录**不重算**（`date` 是已落库的字符串） |
| E16 | 系统时间被手动改动 | "今天"以 `new Date()` 为准，不做校验；顺延横幅的"前一天"同样以本地日期为准 |
| E17 | **导入损坏 / 非法 JSON** | 完整校验后才写入；失败则一条不写、现有数据不变、提示具体原因 |
| E18 | 导入的 `schemaVersion` 高于当前应用 | 拒绝，提示"请升级应用后再导入" |
| E19 | **同设备多标签页同时打开** | 用 `BroadcastChannel('daycell')` 广播写操作，其他标签页收到后重渲染；不支持真正的并发写冲突解决 |
| E20 | Service Worker 更新期间缓存与资源不匹配 | 采用"新 SW 安装后等待，所有页签关闭时激活"策略；避免运行中换资源 |
| E21 | **分类被删除但历史支出仍引用它** | 支出记录保留 `catId`；显示为"已删除分类"并归入汇总的"其他"；不级联删除支出 |
| E22 | 极窄屏（< 320 px） | 月格隐藏花费金额，只留待办进度与想法点；不横向溢出 |
| E23 | 系统开启深色模式 | v0 不做深色主题，但必须保证**不被浏览器强制反色搞坏**（声明 `color-scheme: light`） |
| E24 | 用户从未创建任何分类（首次启动） | 预置 8 个默认分类：餐饮 / 交通 / 购物 / 居住 / 娱乐 / 医疗 / 学习 / 其他 |
| E25 | **农历三十生日落在只有 29 天的农历月**（实现 E13 时实测发现，原 PRD 未覆盖） | 落到该月最后一天（廿九），界面标注"（本月无三十，按廿九计）"。与 E13 可叠加：闰月 + 三十 同时缺失时，按"闰月三十 → 闰月廿九 → 正月三十 → 正月廿九"顺序取第一个可用日期，两个提示都显示 |

## 8. 空状态设计

空状态不是"没内容"，是**引导下一步动作**的机会。每个空状态都必须给出可点的出口。

| 位置 | 触发条件 | 文案与出口 |
|---|---|---|
| **首次启动**（整库为空） | 无任何记录 | 落地即今天的日视图：「DayCell 从第一天开始」+ **待办输入框已自动展开并聚焦**，直接写即可<br/>同时弹出 S1 的"添加到主屏幕"引导 |
| **今天全空**（v6 起最高频的空状态） | 日视图显示今天且三类内容皆空 | 默认状态是**待办表单已自动展开**（见下方规矩 4），此时**不显示**大空状态。<br/>只有用户主动收起后才显示：「今天还什么都没有」<br/>「点各区块右上角的「+ 添加」开始记录」<br/>**不得显示成"错误"或"加载失败"的样子** |
| **其他某天全空** | 日视图显示非今天且三类内容皆空 | 同上（也会自动展开表单）；收起后显示：「这一天还什么都没有」<br/>「点各区块右上角的「+ 添加」**补记**」 |
| **待办区块空** | 无待办且表单未展开 | 今天 →「今天还没有待办」；其他日 →「还没有待办」 |
| **花费区块空** | 无支出且表单未展开 | 今天 →「今天还没有记账」；其他日 →「还没有记账」 |
| **想法区块空** | 无想法且表单未展开 | 今天 →「今天没有记下想法」；其他日 →「没有记下想法」 |
| **整周无记录** | 周视图 7 天全空 | 每行显示「空白的一天」；汇总条显示「无待办 · 0 天有想法 · 本周支出 ¥0.00」 |
| **整月无记录** | 月视图 42 格全空 | 标题栏 `0 天有记录 · ¥0.00`；不额外弹窗打扰 |
| **纪念日列表空** | 未创建纪念日 | 「还没有纪念日」+「添加一个（支持公历或农历生日）」 |
| **导入结果为空** | 备份文件合法但无记录 | 「这个备份里没有内容」，不覆盖现有数据 |

**空状态的四条规矩**：
1. **有表单展开时不显示空状态**（否则"点了+添加还告诉我没有内容"很蠢）
2. 文案说明**下一步做什么**，不只是陈述现状
3. 不用插画、不用 emoji 堆砌，与整体极简风格一致
4. **分区级空文案不得写死"今天"**（v6.1 修）：日视图可以翻到任意一天，看着 9/21 却显示"今天还没有记账"是错的。非今天一律省掉主语——这和刚被移除的顶部框是同一类毛病

> **关于自动展开（v6.1）**：完全空白的一天会自动展开**待办**区块的内联表单并聚焦（待办是 D13 的第一区块，也是场景 A 的高频写入对象）。想法/花费不自动展开，避免一屏三个输入框。用户收起后按日期记住，不再自动弹。
