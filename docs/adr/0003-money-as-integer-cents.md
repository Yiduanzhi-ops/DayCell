# ADR-0003 金额以整数「分」存储

- **状态**：已接受
- **日期**：2026-09-29
- **相关**：PRD §6.2 / US-03 / E5–E7、CORE-API §5.6

## 背景

v0 新增了每日花费，按笔记录。原型 v2 最初用浮点「元」存（`amount: 128.5`），在测试里立刻就暴露了问题：`128.5` 显示成 `¥129`，而 `28.5 + 45` 这类累加在更多小数位下会出现 `73.50000000000001`。

记账数据的特点是**长期累加、必须对得上**。一分钱的漂移在单条记录上无所谓，在"本月支出合计"上就是明显的错误——用户会拿它和银行账单对。

## 决策

**所有金额在 core 层一律以整数「分」（`amountCents: number`）存储和运算。**

- 类型定义：`ExpenseRecord.amountCents`（PRD §6.2），**没有** `amount` 字段
- 录入时立刻换算：`Math.round(parseFloat(raw) * 100)`
- 汇总时只做整数加法
- 显示时才除回元，由三个专用格式化函数负责，**UI 层不得自行做 `cents / 100` 的算术**：

```ts
formatMoney(cents)      // '128.50'   日详情、周行
formatMoneyShort(cents) // '129'      月格（<100 留一位小数，≥100 取整，≥1万 显示 x.x万）
formatMoneyCsv(cents)   // '128.50'   CSV 导出，不带货币符号
```

- 上限：`amountCents ≤ 9_999_999_900`（即 99,999,999 元），超出拒绝（PRD E7）

## 理由

`0.1 + 0.2 !== 0.3` 是 IEEE 754 双精度的固有性质，不是 bug，改不掉。金额是**十进制量**，用二进制浮点表示天然不精确。

整数分是这个问题的标准解法：整数在 `Number.MAX_SAFE_INTEGER`（约 9×10¹⁵）以内完全精确，加法、比较、排序都不会出错。按上限 99,999,999 元算，10 年累计也远不到安全整数边界。

**为什么把格式化也收进 core**：如果 UI 各处自己写 `cents/100` 和 `toFixed`，一定会出现"月格显示 129、日详情显示 128.50、CSV 导出 128.5"这种不一致——原型阶段就已经踩过（测试期望值写错两次都跟这个规则有关）。三个函数集中在 `core/aggregate/money.ts`，规则只有一处。

## 考虑过的替代方案

| 方案 | 为什么否掉 |
|---|---|
| 浮点「元」 | 累加误差，见上。**原型 v2 用的就是这个，已推翻** |
| `toFixed(2)` 后再存字符串 | 避免了误差但无法直接运算，每次汇总都要 `parseFloat` 回来，等于把问题推给调用方 |
| 引入 `decimal.js` / `big.js` | 能解决，但多一个 3–32 KB 的依赖，而"整数分"用 0 依赖达到同样效果。个人记账不需要任意精度 |
| 用 `Intl.NumberFormat` 处理 | 那是**显示层**工具，不解决存储精度问题。我们确实在 `formatMoney` 内部可以用它，但存储必须是整数 |

## 后果

**正面**
- 汇总永远精确，可与银行账单对齐
- 排序、比较、去重都是整数运算，快且无歧义
- CSV / JSON 导出格式稳定

**负面**
- 录入层必须换算，多一步。**缓解**：换算只发生在 `core/validate` 的 `parseAmount` 一处
- 与外部数据（银行 CSV）对接时要做单位转换。v0 不做导入外部账单，暂无影响
- 不支持外币与汇率（v0 假定单一货币 CNY，符号 `¥`）。将来若需多币种，`amountCents` 要配一个 `currency` 字段——**这是唯一可能需要改这条 ADR 的场景**

## 实施要点

- `parseAmount(raw: string): ParseResult<number /* cents */>` 是**唯一**的入口，覆盖 PRD US-03 的全部 6 种输入：空、`0`、`-5`、`abc`、`1e3`、`28.555`
- `28.555` → `Math.round(2855.5)` = **2856**（四舍五入到分，不是截断）
- 顶部快速框的一句话解析（`45 午饭`）走同一个 `parseAmount`，不得另写一套
- 单元测试必须包含：`0.1 + 0.2` 等价场景（`10 + 20 === 30` 分）、`28.555` 舍入、上限溢出、`1e3` 科学计数法
- **禁止**在 core 之外的任何地方出现 `* 100` 或 `/ 100` 与金额相关的字面量。用 ESLint 或 code review 把关
