# ADR-0005 响应式布局：桌面分栏 / 移动三视图

- **状态**：已接受（**v6 修订**：移动端由「底部 sheet」改为「全屏日视图」；桌面端决策不变）
- **日期**：2026-09-29（v6 修订同日）
- **相关**：PRD §5.3 / US-09 / E22 / M17 / M18、SPEC §3.1–3.2、ADR-0007

## 背景

同一份代码要服务两种完全不同的使用姿态：

- **手机**（主要场景）：竖屏约 390×844，单手持握，拇指操作，一次只看一件事
- **桌面**（次要场景）：宽屏，鼠标键盘，可以边看日历边看详情

日详情（待办 / 花费 / 想法三个区块）在两种姿态下的呈现方式是核心布局决策。

**这条 ADR 是被一个真实 bug 逼出来的**：原型 v5 在手机上点开某天后**无法返回**，只能刷新页面。根因见下文，那次事故的教训在 v6 修订后**依然适用**。

### v6 修订的起因

产品默认视图从周视图改为**日视图 + 今天**（PRD §1.4 的取舍：写入优先）。
日视图由此从"点格子才出现的补充面板"升级为**应用的主界面**。主界面继续用弹层承载不再成立，故修订移动端决策。

## 决策

### 桌面（≥ 900 px）：常驻分栏（未变）

```
┌──────────────────────────────┬─────────────┐
│  周/月视图                    │  日详情      │
│                              │  （常驻）    │
└──────────────────────────────┴─────────────┘
```

右栏固定 372 px，点格子直接切换内容，不打断、不遮挡。**不需要关闭按钮**——它一直在那儿。
切到「日」视图时左侧日历收起、日详情占满宽度（PRD M17）。

### 移动（< 900 px）：日 / 周 / 月三视图，各自全屏（v6 改）

```
┌──────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ ← 返回   日 周 月 │   │ ← 返回   日 周 月 │   │ ← 返回   日 周 月 │
│  9月29日 周二     │   │  9月28日–10月4日  │   │   2026年9月       │
│  八月十九         │   │  ┌────────────┐  │   │ ┌──┬──┬──┬──┬──┐ │
│ ───────────────  │   │  │ 周一 28     │  │   │ │  │  │  │  │  │ │
│  待办  3/5        │   │  │ …正文摘要…  │  │   │ ├──┼──┼──┼──┼──┤ │
│  花费  ¥129       │   │  └────────────┘  │   │ │  │  │  │  │  │ │
│  想法  ●2         │   │  （7 行竖排）     │   │ └──┴──┴──┴──┴──┘ │
│  [顶部快速输入框] │   │                  │   │  （42 格，只有指示器）│
└──────────────────┘   └──────────────────┘   └──────────────────┘
      默认落地              ↑ 点某天 → 跳进该日的日视图
```

切换器常驻，顺序固定 **日 → 周 → 月**（PRD D17）。**不再使用底部 sheet 与遮罩。**

**三条返回路径必须全部存在且可用**：

| # | 路径 | 为什么需要 |
|---|---|---|
| 1 | 左上「← 返回」按钮 | 最明确，用户第一眼能找到；回到**来源视图与来源滚动位置** |
| 2 | 系统手势返回（监听 `popstate`） | iOS/Android 的边缘右滑是肌肉记忆，不实现会"手势失灵" |
| 3 | `Esc` 键 | 仅桌面窄窗，但键盘用户需要 |

**硬性约束**：
- **从周/月进入日视图必须记住来源**（哪个视图、哪个日期、滚动位置），返回时精确还原，**不得默认回到今天**
- 日视图内左右滑动 / 点「前一天·后一天」翻日时**保留当前视图**，不得跳回周/月
- 翻到非今天时出现「回到今天」入口；翻到今天时消失
- 展开分区表单时必须 `scrollIntoView({block:'nearest'})`
- 键盘弹起时输入框不得被遮挡（`visualViewport` 或 `scroll-margin-bottom`）
- 跨 900 px 断点切换时**保留选中日期与当前视图**，只重置布局态（分栏宽度等）
- 日视图打开时焦点移入；返回后**归还给触发它的那个格子**

## 理由

**为什么桌面不用弹层**：右栏常驻是桌面端的核心优势——点不同格子时上下文不中断，可以连续对比几天。用弹层会把它变成"打开-关闭-打开"的往复，浪费大屏。

**为什么移动不用分栏**：390 px 宽塞不下两栏。强行分栏意味着每栏 195 px，月格变成 27 px，完全不可用。

### 为什么 v6 推翻了"移动端整页跳转"

原版 ADR 否决整页跳转的理由是：**丢失日历上下文，返回时要重新定位到原来的月份/周**。

这个反对意见在 v6 依然正确，但它的前提变了：

- **v5 时**：日详情是**次要面板**，用户的主任务在日历上，跳走确实打断主任务。
- **v6 后**：日视图是**主界面与默认落地页**。用户打开应用的第一目的就是"看/写今天"，此时不存在"被打断的日历上下文"。

而"返回要重新定位"这个具体代价，用**记住来源**（上面硬性约束第 1 条）就能消除——它比"保留一个只能占 90% 屏高的弹层"便宜得多。

反过来，继续用 sheet 承载主界面有两个无法回避的坏处：

1. **高度被限制在 90% 屏内**。日视图是全文展示（待办/花费/想法不截断），内容一多就要在小窗口里滚，而窗口外还有一层无意义的遮罩。
2. **主界面可以被点遮罩关掉**，这是反直觉的交互——用户不会预期"我的主页面点一下旁边就没了"。

### 那个 bug 的根因（保留，教训在 v6 依然适用）

原型 v5 的 CSS：

```css
body[data-device="phone"] .detail {
  position: absolute; left: 0; right: 0; bottom: 0; top: 0;   /* ← 致命 */
  z-index: 50;
}
.scrim { z-index: 40; }
```

`top: 0` + `bottom: 0` = **占满整个设备高度**。而负责"点一下关闭"的遮罩 `z-index: 40` 在它底下，被**完全盖住，一寸都点不到**。同时：

- grab 条只是装饰，没绑事件
- 手机没有键盘，`Esc` 不存在

三条路全断 → 只能刷新页面。

**这个 bug 在桌面模式下完全测不出来**（桌面是常驻分栏，本来就不需要关闭）。它只在手机模式出现，而且一旦出现就是**功能完全不可用**级别。

**v6 后同一失败模式换了个样子**：不再是"sheet 关不掉"，而是"进了某天的日视图出不来"或"返回后被扔回今天、丢了刚才在看的月份"。
所以约束没有放松，只是从"遮罩 + grab + ✕ + Esc 四条"变成"返回按钮 + `popstate` + Esc 三条 + 记住来源"。
**返回路径冗余**和**不能只依赖键盘**这两条原则原样保留。

## 考虑过的替代方案

| 方案 | 结论 |
|---|---|
| **移动全屏日视图 + 记住来源**（v6 采纳） | 主界面该有的空间；来源记忆消除了上下文丢失 |
| 移动底部 sheet（v5 采纳，v6 废弃） | 主界面被压在 90% 屏高的弹层里；可被遮罩误关。作为**次要面板**时它是合理的，作为主界面不合理 |
| sheet 全屏（`top: 0`）+ 只靠关闭按钮 | **就是出 bug 的那版**。且全屏 sheet 与全屏页面等价，却多背一层遮罩与焦点陷阱 |
| 移动端也用分栏（上下分） | 日历和详情各占一半，两边都不够用 |
| 用原生 `<dialog>` 元素 | v6 后移动端已无模态需求，桌面端也不需要。**不再适用** |
| 取消日视图，手机端只保留周/月 + 弹层 | 与"默认落地今天"的需求直接冲突；且写入路径从 0 次切换退回 1 次 |

## 后果

**正面**
- 移动端主界面拿到全部屏高，全文展示不再被截断
- 少一层遮罩与焦点陷阱，可访问性更简单（不再有 `aria-modal`、焦点困在弹层内等问题）
- 三视图模型统一：日/周/月是**平级**的，不再有"主视图 + 附属弹层"两种心智模型

**负面**
- **返回路径的责任从 CSS 层移到了状态层**：sheet 时代"关掉"是纯视觉操作，现在必须维护一个来源栈（视图 + 日期 + 滚动位置），这是新增的状态复杂度
- 需要处理 `popstate`，即引入 history 状态管理；与"纯前端单页"的简单性有一点冲突
- **仍然是两套布局 = 两倍测试矩阵**。每个交互都要在手机和桌面各验一遍
- 日视图全屏后，用户在周/月与日之间往返时会有整屏切换的视觉跳动，转场需要克制（不要加花哨动画）

## 实施要点

- **不要用 JS 判断设备类型**，用 CSS 媒体查询（原型里的 `body[data-device]` 只是为了在同一页面演示两种模式）
- 断点 **900 px**
- **来源栈只需一层**：`{ view, date, scrollTop }`。v0 不支持多级嵌套导航，返回即出栈到周/月
- `popstate` 处理要与"翻日"区分开：翻日**不 push history**（否则按一次返回只退一天，退不出日视图）
- **触摸目标 ≥ 40×40 px**（PRD §5.5）。「← 返回」不能只有文字大小
- 极窄屏（< 320 px，PRD E22）：月格隐藏花费金额，只留待办进度与想法点
- **测试必须覆盖**：三条返回路径、来源还原（视图+日期+滚动位置）、翻日不丢视图、跨断点保留选中日期
- 断言方式沿用原型 v5.1 的做法：对源码做正则/结构断言（`smoke.cjs` 里直接检查 CSS 组合），因为这类 bug 在 jsdom 里跑不出视觉效果
