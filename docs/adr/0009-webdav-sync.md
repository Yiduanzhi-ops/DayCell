# ADR-0009：跨设备同步走坚果云 WebDAV（BYOB，不建账号体系）

- 状态：**已采纳**（v8.1，2026-10-08）
- 关联：PRD Q5 / CORE-API §4（`byUpdatedSince` 预留）/ ADR-0001（软删除、updatedAt LWW）/ ADR-0006（core 隔离）

## 背景

DayCell 是纯前端 PWA，数据存每台设备浏览器本地（IndexedDB），电脑端与手机端互不相通。
用户希望跨设备同步，且数据不丢失（解决"单机单点"风险）。

## 选型对比（用户拍板）

| 方案 | 结论 |
|---|---|
| **坚果云 WebDAV（BYOB：自带后端）** | ✅ 采纳：零后端成本、数据在自己手里、国内网络稳定；免费额度对个人记账待办足够 |
| GitHub 私有仓库 + PAT | ❌ 弃：用户本地直连 GitHub 超时（需镜像），手机网络更不可控；token 存浏览器有泄露风险 |
| BaaS（Supabase/LeanCloud 等） | ❌ 弃：要注册第三方、管凭据、免费额度限制、数据在别人手里，对单用户工具过重 |
| 自建后端 + 账号体系 | ❌ 弃：成本高，个人工具不需要；"每人填自己的坚果云账号"已天然实现互不干扰 |

## 决策

1. **WebDAV 是"拉取"模型，不是"推送"**：自动同步 = 打开网页 pull 一次 + 本地变更防抖 push；
   保留手动「立即同步」补盲区（另一设备改过而本页一直开着时）。
2. **数据格式复用备份 JSON**（`BackupFile`），同步文件即云端最新备份——同步同时是异地备份。
3. **合并语义：id 级 last-write-wins**（≠ 备份导入的"本地优先"）。
   - 同 id 取 `updatedAt` 较新者（含墓碑 → 删除可同步）；远端独有墓碑跳过；本地独有保留
   - 不同 id 天然合并，两设备各自新增互不覆盖
   - 唯一数据丢失场景：两端**同时**改同一条（个人单用户概率≈0），按 LWW 覆盖
4. **写回必须 `keepTimestamps`**：否则合并写库的 updatedAt 全变"刚刚"，下次比较反向覆盖（ADR-0001 同款陷阱）。
5. **配置存 localStorage，不进 IndexedDB、不进备份文件**：
   - 密码不随备份到处走；备份/导出不含同步凭据
   - 丢失只影响"自动同步"：重填三个值即可，数据本体在本地库 + 云端
6. **防循环**：pull 合并写库期间置 `merging` 标志，写库触发的 `schedulePush` 直接跳过，
   否则 拉取→写库→推送→另一端拉取 无限循环。
7. **触发点：包装 store 写入口**（`put`/`putMany`/`putSetting`），在 `initCore` 的
   `wrapStore` 注入点、`createRepos` 之前应用——repo 全部写操作一处包装全覆盖，
   不逐个改 repo/action。
8. **多用户隔离靠"一人一个坚果云账号"**：应用密码绝不外传；网页本身公开但数据私有。

## 代价与边界（明示给用户）

- 分钟级模型，非实时（WebDAV 无服务器推送）；两设备同时开着时改动不会即时互见，点「立即同步」可马上拉
- 坚果云免费额度有限（月度上传流量），不做定时轮询以免耗流量
- 配置存在浏览器本地，被攻破有泄露风险；应用密码只具备 WebDAV 读写权限，动不了坚果云账号本体
- 坚果云不可用时本地照常，只暂停同步
